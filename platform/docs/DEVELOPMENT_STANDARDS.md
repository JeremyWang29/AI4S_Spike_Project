# AI4S 平台研发代码质量与交付规范

版本：V1.0｜2026-09-29｜适用范围：`platform/` 的前端、后端、任务、数据迁移、部署配置及其测试。本文约束从 M1 起的新增开发和受影响代码；历史代码在修改时按受影响范围逐步治理。产品事实以[产品设计方案](../../AI4S_project/outputs/research-platform-design-20260907/产品设计方案.md)为准，模块所有权和状态契约以[技术方案](../../AI4S_project/outputs/architecture/architecture-ai4s-2026-09-09/技术方案.md)为准，阶段放行以[验收目录](../../AI4S_project/outputs/architecture/architecture-ai4s-2026-09-09/验收目录.md)为准。本文规定研发质量门槛，不把设计文字当作功能已实现。

## 1. 优先级与基本原则

当目标冲突时，按**科研结论及业务状态正确性→权限、许可和数据安全→可恢复与可追溯→可维护性→经测量的性能与成本→代码行数**排序。不得为缩短代码或加快页面响应而降低前四项。ISO/IEC 25010:2023可作质量维度参考，项目门槛仍以本文和可执行验收证据为准。[ISO/IEC 25010:2023](https://www.iso.org/standard/78176.html)

1. **正确**：业务术语、输入边界、状态转换、分母与适用范围明确。查全、查准、Gold、检索停止和证据等级由其业务模块裁决；模型输出只是候选，不取得通过状态。
2. **易读**：名称表达业务含义，函数和类有清楚职责，控制流可顺序理解；注释解释非显然的规则与取舍，不复述代码。项目内一致性优于机械追求行数。[PEP 8](https://peps.python.org/pep-0008/)
3. **高内聚、低耦合**：按业务事实划模块，唯一写入者明确；跨模块通过公开命令、查询、版本化 DTO 与事件交互。页面、Worker、Admin不得绕过应用服务直接改变其他模块的业务真值。具体边界见[模块开发与故障定位约定](../../AI4S_project/outputs/architecture/architecture-ai4s-2026-09-09/模块开发与故障定位.md)。
4. **适度简洁**：消除确有相同语义的重复；保留有业务含义的显式步骤。不得为了抽象而引入只服务单一场景的框架、隐式魔法或深层继承。不存在统一的函数行数、类数或文件数合格线。
5. **可复现、可演进**：规则、输入快照、许可、模型／提示、平台适配、方法参数和结果保留版本及因果引用。数据迁移、接口变更与历史读取需要明确兼容及恢复方案。

## 2. 每个开发任务的必备交付物

开发前记录一张任务契约卡，可写在任务规格或 PR 描述中，不要求另建重复文档：用户动作与成功条件；主责模块和唯一写入对象；输入／输出版本及接口；权限、许可和状态守卫；失败、重试、撤回及下游失效；需验证的正常与异常场景。未知项标“待定”并在实现依赖它之前解决，不能让页面默认值代替业务决策。

交付时附可复核证据：改动范围与原因、关联规格／验收场景、自动检查结果、必要的人工或真实平台验证、数据迁移与性能／成本影响。只报告实际运行的检查；模拟模型、合成题录或 UI 预览不能写成真实科研有效性通过。文档和代码状态不一致时，先在交付说明标明差距并明确后续任务。

## 3. 代码实现约束

| 关注点 | 强制约束 | 评审要看什么 |
| --- | --- | --- |
| 结构 | 业务规则放在拥有模块；视图、序列化器和组件只协调输入输出，不复制业务裁决 | 修改一条规则是否只需改其所有者及明确的消费契约 |
| 接口 | 写命令校验授权、许可、期望 revision 和幂等键；错误码区分无效、无权、冲突、外部失败与质量未通过 | 重试、并发和旧版本是否可预测、可恢复 |
| 数据 | 数据库约束保护唯一性与不可变版本；迁移可在空库和已有数据上验证，说明前向、兼容与回滚／补救路径 | 历史对象能否读取，旧任务能否安全结束 |
| 前端 | 呈现后端业务状态；待配置、待人工、探索、已通过等状态不混用；表单校验提升体验但不代替后端守卫 | 刷新、切换项目和失败重试后是否显示真实状态 |
| 后台任务 | 以数据库任务为真值，执行可幂等或明确对账；外部付费调用不在数据库锁内，也不因超时盲重试 | 重复通知、迟到结果、取消和未知费用的处理 |
| 安全 | 所有读取和写入按项目、角色、材料许可校验；敏感内容不进入普通日志、异常消息或无授权模型上下文 | 越权、许可撤回、导入恶意内容与日志泄漏测试；Web 安全清单参考 [OWASP ASVS](https://owasp.org/projects/asvs) |
| 依赖 | 使用锁定版本；新依赖须说明用途、维护与安全影响，避免仅为简单功能增加重量级组件 | 现有库或标准库能否满足、升级成本如何 |

## 4. 验证和性能门槛

**测试分层。** 对计算、状态机、权限和许可写有判定力的模块测试；跨模块变更补契约测试；用户关键旅程补 API／页面验收。至少覆盖适用的正常、越权、版本冲突、重复提交、缺失输入、失败恢复与依赖失效。检索平台语法、Gold 独立性、科学质量及真实模型效果另以真实样例验收，不能由 mock 成功代替。测试应检验业务可观察行为，避免只把实现步骤重写一遍。

**性能。** 先使用技术方案规定的试点规模及服务目标作为门槛：普通查询服务端 p95≤2 秒；长任务在请求体接收完成后 2 秒内持久化受理并返回任务 ID。上传、排队、外部模型和人工等待分开计时。只有在同一数据规模和基线下发现瓶颈，才据测量优化 SQL、索引、批处理或缓存；优化须保留结果一致性及权限边界。AI 成本比较采用含重试、升级与人工返工的端到端总成本，质量不达基线不得仅因便宜而切换路线。指标定义和用例监控见[模型调用与成本模块](../../AI4S_project/outputs/research-platform-design-20260907/modules/08-模型调用与成本.md)。

**可诊断。** 用户动作、异步任务和模型尝试能以 `trace_id`、对象版本、`task_id`／`attempt_id` 关联；记录状态变化、原因码、耗时、成本和责任模块，不在常规日志存材料正文、受保护 Gold 或完整提示。故障能定位到所属模块、输入版本和恢复动作。

## 5. 现行自动检查与待建设门槛

当前仓库已提供以下检查命令，Windows PowerShell 下使用 `npm.cmd`。每次受影响的代码变更至少运行对应检查；若环境阻断，报告命令、原因和未验证范围，不能写“通过”。

```powershell
uv sync --project platform/backend --frozen
uv run --project platform/backend python platform/backend/manage.py check
uv run --project platform/backend python platform/backend/manage.py test platform/tests
npm.cmd --prefix platform/frontend ci
npm.cmd --prefix platform/frontend test
npm.cmd --prefix platform/frontend run build
```

上述命令不等于完整质量覆盖。当前前端源码主要是 JavaScript，尚未启用 TypeScript 类型检查；项目也尚未配置统一的 Python／前端 lint、格式检查和依赖安全扫描。这些属于**待建设的持续集成门槛**，不能在验收记录中宣称已自动执行。后续按[技术方案的 Vue＋TypeScript 方向](../../AI4S_project/outputs/architecture/architecture-ai4s-2026-09-09/modules/00-总体与模块所有权.md)逐步迁移受影响前端代码，先明确兼容范围、锁定工具与规则，再把类型、格式、静态检查和安全扫描加入 CI；新增门槛须能在本地复现，历史存量问题可分批清理，但新改动不得增加同类问题。

## 6. 合入与阶段放行

每项变更需完成：①契约卡；②受影响代码、数据库迁移与文档同步；③适用的自动测试及真实样例证据；④安全、权限、许可、性能和 AI 费用影响检查；⑤评审记录。涉及 Gold、检索指标、停止决定、跨项目访问、付费模型或数据删除的改动，须由非实现者重点核对业务门槛和异常路径；人员暂不可用时保留待复核状态，不把未复核能力作为正式通过。阶段放行还须对照[验收目录](../../AI4S_project/outputs/architecture/architecture-ai4s-2026-09-09/验收目录.md)逐项核证。

确有紧急修复可缩小验证范围，但需记录原因、风险、负责人、补验期限与回退办法；不能免除权限、许可或数据完整性检查。违反规范或发现无法复现的验收证据时，修复归属模块及其测试，不以全局特判掩盖问题。
