# AI4S研究决策平台分阶段开发计划

> 版本：V1.3
> 日期：2026-09-23
> 面向：3—5人核心团队、10个邀请制账号的受控服务器试点
> 贯穿验收任务：铁死亡介导癌症放疗抵抗

## 1. 计划目标与依据

本计划将已验证的前台交互原型逐步替换为服务端真实业务能力，以一次真实选题任务贯穿“登录—建项—范围—检索—Gold—语料—分析—证据与决策”。每个阶段必须交付可操作、可测试、可追溯的用户增量，不以界面完成代替业务验收。

## 2. 已有基线（保留2026-09-11计划快照）

原计划编制时的代码基线为 Git 提交 `4af37cba1bf82d4813091743f01c0c29ef51b261`。已完成真实会话、项目列表、用户隔离的原子建项和八步交互预览；后端31项、前端16项自动测试通过，并完成桌面和390px移动宽度走查。

该基线属于 **M0交互和建项原型完成**，不代表M0正式验收完成。当前`sessionStorage`中的范围、检索、Gold、语料和分析数据仅是交互预览，必须按阶段替换为业务模块拥有的服务端状态。

## 3. 总体节奏

原V1.0基准开发期为20周，另保留最多2周机动时间，因此原计划日历范围为 **20—22周**；V0.12新增工作尚未重新估时，不能沿用此数作为交付承诺。时间是3—5人核心团队的参考值，阶段放行以验收证据为准。M1和M2结束后根据真实平台导出差异、解析失败样例和检索迭代次数重新估算后续工期。

| 阶段 | 参考周期 | 用户可得结果 | 试用节点 |
|---|---:|---|---|
| M0 入口与范围硬化 | 2周 | 安全登录、原子建项、真实范围版本和可恢复流程 | 内部验证 |
| M1 检索准备 | 4周 | 真实范围→拆块追问→方案确认→平台式→外部执行→题录回传 | 邀请用户流程试用 |
| M2 检索评估闭环 | 4周 | Gold、多轮调优、独立验收和停止决定 | 真实检索方法验证 |
| M3 语料与基础分析 | 4周 | 固定语料、权限受控全文和可复算基础分析 | 10账号小规模正式试点 |
| M4 研究决策 | 3周 | 导航切面、证据/空白、候选课题和定题包 | 完整真实选题验收 |
| M5 图谱后台与共享 | 2周 | 私人/成型图谱、贡献审核、撤回和邻域权益 | 指定账号封闭测试 |
| M6 质量与试点验收 | 1周 | 质量/成本基线、容量、灾备和试点决策 | 试点继续/调整决策 |

并行规则：开发主力只实现当前阶段的业务链；下一阶段只可提前完成数据模型、端口契约、合成测试夹具和技术验证，不在上游规则未验收时全面开发下游界面。

## 4. 阶段计划

### M0：入口与范围硬化（第1—2周）

**阶段目标**

将已有登录、建项和范围交互原型转为可在受控服务器上安全恢复和审计的真实能力。

**主要任务**

1. 完成项目所有者、研究者、方法审核者和管理员四类最小权限，对列表、详情、文件和命令分别校验。
2. 完成邀请、密码重置、会话撤销、登录限速和关键操作审计。
3. 保持建项事务的用户域幂等，补齐DependencyEdge、Outbox事件和WorkflowProjection可重建测试。
4. 实现四组范围访谈的服务端草稿、候选词决定、矛盾清零和ResearchConstraint版本确认。
5. 修复已登记的旧API输入验证、候选/奖励信任边界、首次部署迁移与非开发密钥失败关闭问题。
6. 将开发、验收、试点环境的数据库、文件前缀、队列和配置隔离。

**阶段产物**

- 可部署的同域会话、权限和审计基线。
- 真实Project、ResearchConstraintVersion、DependencyEdge、WorkflowProjection和事件链。
- 范围修改后下游失效与历史保留的契约测试。
- 受控服务器开发/验收部署脚本及迁移运行手册。

**放行门**

- 重复建项只生成一个完整项目，中途失败不留半成品。
- 用户无法读取或推测未授权项目；四类角色关键负例通过。
- 范围未补全、候选未处理或矛盾未清零时不能确认。
- 投影删除后能从正式对象和事件重建；任务失败显示恢复动作。
- 首次部署自动完成数据库迁移，非开发环境缺密钥时拒绝启动。

### M1：检索准备（第3—6周）

**阶段目标**

让用户从已确认范围生成可核对的平台表达式，在外部平台人工执行后回传真实题录，形成不可变原始来源和可重放解析记录。

**主要任务**

1. 建立检索块、方案任务／批次、问题前沿和显式确认；再生成与平台无关的AST及QueryBundleVersion，不把平台文本当正式逻辑。
2. 优先完成CNKI、Web of Science和PubMed的子库、字段、运算符、转义、过滤和规则版本；其余平台保持“规则待核对”。
3. 实现规则、语法能力、语义一致性、实际执行、回传完整性和Gold/查准质量六类检查的分层状态。
4. 实现SearchRun（原计划称ManualRetrievalRun），保存原样执行式、时间、平台命中数、导出数、过滤、排序和截断说明。
5. 支持CSV/TSV、RIS和BibTeX，并为CNKI、WoS、PubMed真实导出样例建立适配器。
6. 原文件按指纹不可变保留；将SourceRecord与RecordOccurrence分开，实现批次内/跨批次去重和逐条解析错误。
7. 实现高被引前10、一区最新10篇的重叠/缺额说明，产生可确认的概念词表和项目知识候选。

**阶段产物**

- 三个平台经真实样例验证的编译/反解析规则。
- 不可变导入批次、解析覆盖报告、去重报告和原始文件指纹。
- 可由用户确认的种子集、ConceptVersion和基础项目知识输入。
- 从平台选择到回传核验的前后端真实状态。

**放行门**

- 每个已启用平台至少3组真实输入通过编译、平台执行和反解析对比。
- 重复上传不重复生成业务记录；部分导出、损坏、密码保护和未知格式均有明确状态与恢复动作。
- 命中数、导出数、解析数、去重数和纳入数分开展示，部分回传不能支持“未检索到”结论。
- 至少3名目标用户完成范围、选平台、外部执行和导入，无需开发人员修改数据。

### M2：检索评估闭环（第7—10周）

**阶段目标**

实现可复算、无泄漏的Gold调优和独立验收闭环，让用户在达标或有记录地停止后进入语料阶段。

**主要任务**

1. 建立GoldRecord、GoldSetVersion和EvaluationPackageVersion，有效Gold总数不少于50条，调优/独立验收包均含正负例。
2. Gold正例计算查全，Gold负例只作误检回归；实际结果集以全量标注或冻结的分层随机样本计算查准。
3. 分层样本保存总体版本、分层定义、随机种子、样本项和置信区间；20篇固定随机诊断仅用于调优。
4. 实现已确认方案→QueryBundleVersion→人工执行→导入→按评估范围合并→评估→回传追问→新方案确认的循环；语义等价编译不重复范围访谈。
5. 调优和独立验收两阶段均使用未舍入查全率、查准率≥0.85，unknown=0，且六类检查完成。
6. 记录验收包的暴露史；任一材料用于调优后，整包永久失去独立验收资格。
7. 实现validated、user_stopped、externally_blocked和scope_superseded四类停止决定；非通过停止必须保存原因、指标、限制和下一动作。

**阶段产物**

- 可重现的Gold构建、标注、分包和暴露记录。
- 查全/查准指标、分母、抽样和置信区间报告。
- 检索式版本比较、误检诊断和四类停止收据。
- 解释每个阻断及恢复动作的Gold与正式检索页。

**放行门**

- 49条Gold、零分母、unknown>0、84.96%、负数/非数值、检查缺失和包泄漏均不能validated。
- 同一真实主题至少完成两轮人工平台检索，新表达式、执行回传和评估全部可追溯。
- 独立包暴露后不得恢复原资格；新建包才能重新验收。
- 方法审核者能按原始记录重算所有正式指标。
- M2结束时根据实际迭代次数和人工标注工时重估M3—M6。

### M3：语料与基础分析（第11—14周）

**阶段目标**

将有记录的停止决定转化为独立DatasetSnapshot，并在数据、字段、引文边和全文许可允许的范围内运行可复算基础分析。

**主要任务**

1. 实现纳排、去重和覆盖限制确认后的DatasetSnapshot，与SearchStopDecision分开版本和审批。
2. 实现MaterialAccessDeclaration，在上传、任务上下文和结果交付三处检查本地保存、解析、外发、派生保留和导出权限。
3. 实现PDF流式上传、文件签名、大小/页数限制、隔离解析、页号片段和失败人工处理。
4. 逐能力建立AnalysisCapabilityAssessment，明确enabled、blocked和exploratory_only及缺少依赖。
5. 实现描述性统计、发文趋势、关键词共现/突现、前沿主题簇和基础引文网络；引用数与真实CitationEdge分开。
6. 实现VOSviewer、CiteSpace和Bibliometrix兼容导出，导出中保留数据快照、字段及方法版本。
7. 准备统一模型网关、许可策略、缓存/在途合并、预算账本和质量基线夹具，本阶段不让模型生成正式统计结论。

**阶段产物**

- 独立语料快照、全文权限声明、解析覆盖和失败报告。
- 绑定快照、字段、切面、词表、方法和随机种子的分析产物。
- 平台内基础统计/图形和三类外部计量工具导出包。
- 每个分析卡的数据来源、适用性、限制和恢复动作。

**放行门**

- 相同输入版本、方法和随机种子可复算得到相同结果。
- 部分回传、缺引文边、缺字段或全文不允许处理时，受影响能力必须阻断或降为仅探索。
- 任一报告可追溯至DatasetSnapshot和原始SourceRecord，图表不暗示共现为因果。
- 10个邀请账号中至少3人能独立完成从建项到基础分析的实际任务。

### M4：研究决策（第15—17周）

**阶段目标**

将固定语料和可复算分析转化为可追溯的研究方向导航、证据状态、研究空白和候选课题，并以人工方法审核作为放行条件。

**主要任务**

1. 实现用户定制切面、个人切面模板与项目切面版本，支持复制、升级和另存。
2. 基于检索结果分析规模、趋势、热点迁移和潜在衰退信号；CNKI/WoS数据允许时补高被引、奠基文献和引文图谱。
3. 实现“尚未检索到证据”、“证据不足”、“证据相互冲突”的独立并存状态和原文定位。
4. 按七类空白归类：证据/内容、对象/人群、方法、理论/视角、场景/地理/时效、矛盾、技术/实践/政策。
5. 从局限/展望、引文双向追踪、文献计量结构和用户切面生成空白候选及来源链。
6. 候选通过最近12个月窄检索补查、PICOS或“对象+变量+条件”结构化、价值/可行性与专家核查后才能进入定题。
7. 将模型限定为范围追问、概念候选、受控信息抽取和说明；所有输出是候选，接受后才进入正式对象。
8. 实现模型调用前的用途/许可、缓存/在途、预算预留、ContextManifest及输出结构/来源检查。

**阶段产物**

- 可版本化的研究方向切面和导航报告。
- 证据节点、主张、条件、关系和三类未确定状态。
- 七类空白矩阵、补查记录、三关结果和专家意见。
- 候选课题、科学问题、研究假说、技术路线、可行性和风险包。

**放行门**

- 任一空白不得因为“结果中没有”直接称为真空白，必须有覆盖声明、补查和专家结论。
- 模型结果不能自我批准；受限材料不外发，未配置模型时流程可以人工继续。
- 一次真实主题从DatasetSnapshot到至少2个候选课题全链可追溯，其中至少一个能以书面理由通过或被否决。
- 产品、科研方法和技术负责人共同签收完整选题链。

### M5：图谱后台与共享（第18—19周）

**阶段目标**

在私人项目图谱可用的基础上，建立平台成型图谱、低重合贡献、双人复核、发布、撤回和90天相邻领域权益闭环，仅向指定试点账号开放。

**主要任务**

1. 分离用户导入构建的私人图谱与平台收集/审核的成型图谱，所有取用点先限定权限域。
2. 实现实体、关系、来源和版本规范化，重合率依据和阈值必须可追溯，阈值由管理员版本化配置。
3. 贡献者确认最终子集和许可；内容与许可由不同审核人通过，发布事务重新核验当前图谱和权限。
4. 同一贡献版本只产生一个奖励资格；用户选择相邻领域后创建90天许可区间，不直接改剩余秒数。
5. 实现暂停、撤回、到期、版本升级、迟到事件和FIFO结算的追加账本及对账。
6. 将智慧芽纳入专利输入适配的封闭验证，复用QueryVersion、ImportBatch和评估范围，但文献与专利分别验收。

**阶段产物**

- 私人、共享候选和已发布图谱的权限隔离与版本管理。
- 贡献、审核、发布、奖励、激活、撤回和对账工作台。
- 智慧芽导入和专利检索表达式的适配验证报告。

**放行门**

- 贡献者不能伪造审核人、重合率或许可；发布后才能生成唯一资格。
- 撤权立即阻断新读取、检索、模型输入和交付，不因定时任务滞后延长权益。
- 并发激活、迟到撤回、重复事件和恢复重放后的权益守恒。
- 指定试点账号能使用获授权的相邻图谱，无权用户不可见内容或存在细节。

### M6：质量与试点验收（第20周）

**阶段目标**

用冻结的质量、成本、容量、恢复和用户价值证据判断试点是否扩大，不以功能数量作为成功标准。

**主要任务**

1. 冻结模型质量和人工工作量基线，验证降本路由不降低各项质量、不增加人工工时且无新增严重科学错误。
2. 完成10账号、3人同时操作、单项目2000条题录和200份全文的容量与故障测试。
3. 验证API p95、错误率、队列最旧任务、Outbox、磁盘、备份/WAL水位、权限拒绝异常和预算未知金额告警。
4. 执行最近一致点RPO≤1小时和RTO目标的隔离恢复演练，恢复后先重放并校验权限/水位再开放。
5. 汇总用户任务完成率、检索迭代效率、双85%达标率、人工审核工时、严重科研错误、模型成本和用户留存。
6. 形成继续投入、限制范围继续试点、返回某阶段修正或停止的书面决策。

**放行门**

- 所有试点指标的定义、数据来源、时间窗口和基线已在试点前冻结。
- 容量、备份、恢复、删除、权限和付费调用对账均有实测证据。
- 不存在未关闭的严重科学错误、数据越权、许可违反或无法恢复的关键事务。
- 产品、科研方法和技术负责人联合签署试点结论。

## 5. 团队与责任

| 职责 | 建议投入 | 核心责任 |
|---|---:|---|
| 产品／科研方法 | 1人 | 用户任务、范围、检索方法、Gold、统计解释、空白三关和阶段签收 |
| 后端／数据 | 1—2人 | 领域对象、事务、任务/事件、导入解析、统计、权限和追溯 |
| 前端 | 1人 | 八步工作台、错误恢复、可用性、响应式布局和真实API适配 |
| 运维／测试 | 0.5—1人 | 环境、CI、容器、备份恢复、容量、安全和验收证据 |
| 领域顾问／方法审核者 | 按节点参与 | Gold标注规则、检索失败样例、分析方法、空白和定题核查 |

同一人可兼任，但阶段记录必须明确产品、科研方法和技术签收者。审核者不得用前端传入的`approved=true`代替服务端资格核验。

## 6. 每个阶段的标准工作流

1. **准备**：将本阶段产品规则转为规格、端口契约、状态机和验收场景，标明不实现的能力。
2. **实施**：按业务聚合实现服务端命令和事件，再将前端预览状态替换为API DTO。
3. **验证**：执行领域单元、API契约、真实任务、权限及失败恢复测试；生成可追溯验收证据。
4. **评审**：开发者之外的人员审查流程边界、科研规则、输入异常、权限和测试缺口。
5. **试用**：部署到独立验收环境，使用合成异常数据和获许可的真实课题数据。
6. **签收**：产品、科研方法和技术负责人核对放行门、未完成项和风险，决定进入下一阶段或返回修正。

## 7. 质量和发布约束

每个阶段的最低完成定义：

- 产品方案、技术决策、OpenAPI/事件契约、界面状态和测试使用同一套名称与规则。
- 对外命令具有权限、幂等、期望版本、业务错误和审计；异步命令持久化受理并可恢复。
- 统计、权限、状态、账本和规则计算不调用大模型；模型输出不直接成为审批或科学事实。
- 浏览器不保存长期Bearer token；服务器是正式业务事实来源，队列、索引和前端投影可重建。
- 测试至少包括正常路径、边界值、无效输入、越权、并发、重试、中途失败、旧版本完成和恢复重放。
- 发布到受控服务器前，迁移向前/回滚、配置校验、备份可恢复性和回退方案均完成。

## 8. 试点指标

| 指标 | 定义 | 首轮用途 |
|---|---|---|
| 核心任务完成率 | 无开发人员代操时，用户完成本阶段任务的比例 | 发现流程与恢复指引缺口 |
| 检索迭代效率 | 从范围确认到停止决定的轮次、耗时和人工操作数 | 判断概念词表、诊断和恢复动作的价值 |
| 双85%达标率 | 在无独立包泄漏下，调优和独立验收均达标的项目比例 | 衡量检索方法与数据质量 |
| 人工审核工时 | 范围、Gold、方法、证据和候选各环节的实际工时 | 防止降成本以增加人工为代价 |
| 严重科研错误 | 会改变范围、检索验收、证据状态或定题决策的错误 | 作为模型路由和正式放行的否决指标 |
| 模型成本 | 按任务类型、输入指纹、供应商、币种和实际/未知费用统计 | 评估缓存、路由和非模型规则的降本效果 |
| 用户留存 | 邀请用户在后续周期主动返回并继续项目的比例 | 辅助判断平台是否解决持续研究任务 |

试点前必须冻结指标口径、时间窗口和基线。本计划不在没有基线数据时虚构通过阈值；M6由三方签收人根据冻结数据作决定。

## 9. 风险与暂停条件

| 风险 | 前置控制 | 暂停／恢复条件 |
|---|---|---|
| 平台规则变化或导出差异 | 规则版本、真实样例、编译/反解析测试 | 无法重现真实查询时暂停该平台；新规则核对后恢复 |
| Gold不足或评估泄漏 | 资格、分包、暴露史和未舍入指标 | 无合格独立包时不能validated；新建并封存验收包后恢复 |
| 材料许可不明 | 未知按拒绝，每个取用点重新校验 | 受影响的解析、模型、导出和交付暂停；取得可追溯许可后恢复 |
| 分析数据不可追溯 | 快照、InputRef、指纹和方法版本 | 不发布正式结论；重建完整来源链并复算后恢复 |
| 模型质量或成本恶化 | 冻结质量/人工基线、预算预留和费用对账 | 退回人工或已通过路由；独立评测通过后再启用新路由 |
| 跨层规则冲突 | 产品、架构、契约和测试同步评审 | 暂停相关实现；先更新决策和契约，再修改实现与测试 |
| 关键安全或恢复缺口 | 权限负例、异机日记、备份和恢复演练 | 不进入下一阶段或不扩大试点；缺口关闭并复验后恢复 |
