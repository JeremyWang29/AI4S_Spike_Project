# 模块开发与故障定位约定

版本：T1.7｜2026-09-29。本文是[技术方案总纲](./技术方案.md)的实施约定；业务规则以[产品设计总纲](../../research-platform-design-20260907/产品设计方案.md)及所属产品模块为准。这里的边界是研发目标，现有代码达到何种程度仍须逐项验收。

## 1. 以业务事实确定模块，不以页面确定模块

| 代码模块 | 唯一写入的业务事实 | 对外提供的最小能力 | 先查看的故障证据 |
| --- | --- | --- | --- |
| `identity` | 用户、邀请、成员及权限版本 | 当前角色与授权裁决 | 登录请求、成员版本、拒绝原因和审计 |
| `projects` | 项目、范围回答、范围版本、工作流投影 | 建项、范围确认、项目状态读取 | 命令 revision、回答快照、投影水位 |
| `retrieval` | 领域模板、一级分面建议／决定、检索块、方案、执行与停止决定 | 分面建议、方案编译、执行登记和停止裁决 | 项目输入及模板指纹、分面决定、方案／平台规则版本、六关检查 |
| `materials` | 导入批次、来源、文件、去重和语料快照 | 导入、许可校验、材料读取 | 文件哈希、批次、解析错误、来源和许可 |
| `evaluation` | Gold 标签、原式命中、平台收录、抽样、评估包与退役 | 隔离评估、范围级查全／平台内诊断、查准及资格裁决 | Gold 发现路径与分区、原式命中和收录两轴凭据、总体版本、样本策略及分母 |
| `knowledge` | 概念词表、私有图谱、证据关系 | 候选术语、证据检索和关系核查 | 概念版本、关系证据、来源及适用性 |
| `analysis` | 切面、分析策略、分析快照 | 统计、聚类、引文和方向结果 | 语料快照、方法版本、准入和任务结果 |
| `research` | 空白候选、补查报告和定题框架 | 三关核查、候选课题与风险 | 候选来源、最近补查、人工审定状态 |
| `assets` | 图谱贡献、审核、发布和撤回 | 贡献审核、资产发布与许可状态 | 贡献包、审核记录、发布版本和许可 |
| `entitlements` | 资格、权益、奖励账本 | 当前使用权与到期／撤回裁决 | 资格事件、权益账本、当前有效期 |
| `execution` | 任务、尝试、依赖和事件投递 | 幂等提交、重试、取消和恢复 | trace ID、task ID、attempt、outbox／inbox |
| `models` | 模型路由、上下文清单、费用与基线 | 受控候选生成和质量门槛 | 模型／提示版本、输入指纹、调用状态、费用 |
| `operations` | 审计、删除与恢复记录 | 审计查询、备份恢复和监测 | 审计链、恢复清单、告警时间线 |

聚合页面可以读取多个模块的 DTO，但不能拥有这些模块的通过状态。一个功能横跨两行时，拆成各自的写命令和一个显式交接契约；不增加“总控表”来复制业务事实。

## 2. 每个开发任务的契约卡

启动任务前在规格或任务单中写清下列字段，未确定的字段标注“待定”，不得凭页面交互隐含决定：

1. **所有者与事实**：本任务修改哪个模块、哪种对象、由谁唯一写入；关联的产品规则和技术模块链接。
2. **输入与输出**：公开命令／查询、版本化 DTO、输入来源、许可、权限上下文和输出适用性；写操作必须有期望 revision 与幂等键。
3. **状态与失败**：成功、待人工、受阻、过期、撤回等状态，以及可恢复动作；把权限拒绝、输入无效、版本冲突、平台不支持、外部失败和质量未通过分开表达。
4. **下游影响**：哪些结果依赖本次输出；输入变化时哪些结果失效、哪些历史版本仍可读；异步事件带因果引用和版本。
5. **验证证据**：模块规则测试、跨模块契约测试、权限与许可测试、迁移／恢复测试，以及涉及真实检索平台或模型时的独立验收记录。

前端只调用公开 API；Worker、Admin 和同步 API 走同一个应用服务。模块间不直接写其他模块的 ORM 表，不通过共享临时字段决定通过资格。数据库约束保护不可变版本和唯一性，接口测试保护调用方契约。

## 3. 最小可诊断记录

每个用户动作应能关联 `trace_id`、项目 ID、操作者与角色、模块、命令／任务 ID、输入对象及 revision、结果对象版本、状态、失败码和发生时间。材料与模型调用额外关联来源／许可及输入指纹；后台任务关联 attempt、重试原因和外部平台／模型适配器版本。日志只记可追踪标识与摘要，不在日志中泄漏全文、受保护 Gold 或模型敏感上下文。

排障按以下顺序进行：复现用户动作与项目版本→查授权和许可→查所属模块的命令及业务状态→查异步任务与事件水位→查下游适用性和投影→复跑模块测试／契约测试。若页面和业务事实不一致，先从模块 DTO 重建投影；若真实平台检索式失败，保留平台规则版本和原始错误并在 `retrieval` 适配器修复；若 Gold 指标异常，先核对发现路径、声明范围、原式命中、平台收录归因、分区、分母与样本策略，不让模型读取保护集。

## 4. 发布与变更门槛

一次模块变更必须同时更新所属产品模块、技术模块与公开契约；受影响的其他模块只更新其消费契约和测试。数据库迁移说明前向与回滚路径，旧对象读取兼容窗口要有明确期限。模块测试通过后，再执行受影响的跨模块场景；真实平台规则、模型质量、科学判断和许可效果均以各自的验收记录判定，不由合成测试替代。故障归因和修复记录最终回写到该模块的规格、测试和运行手册。

## 现行文档维护规则

每项规则仅由所属模块定义，跨模块页面使用链接和DTO。API端点及错误信封仅维护在[T07](./modules/07-数据与API契约.md#api)；验收编号与阶段在[验收目录](./验收目录.md)，产品／技术断言分别在P11与验收映射。变更需同步对象、命令守卫、事件、失效范围、错误码、对应场景；旧行号仅供历史迁移。来源状态、收录观察与检索命中是三个独立事实，排障需带各自对象版本和执行时间窗。
