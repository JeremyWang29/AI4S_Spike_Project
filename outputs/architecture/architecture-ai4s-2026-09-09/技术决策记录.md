## 2. V0.11同步决策

用户在产品流程完善后确认Q1—Q21均按建议，并确认同步修改四份技术文档。该轮固定以下实现决定：

| 决策主题 | 最终决定 | 直接实现后果 |
|---|---|---|
| 主流程与所有权 | 登录→建项→范围访谈→平台与检索式→人工检索／导入→Gold和查准迭代→停止→语料→分析；projects拥有项目、范围和投影 | 模块不能各自维护“当前步骤”；页面从WorkflowProjection读取恢复动作 |
| 原子建项 | Project、ResearchConstraint v1草稿、依赖、WorkflowProjection和Outbox同事务创建；用户域幂等、`expected_revision=0` | 任一写入失败全部回滚；重投返回同一项目，不能出现孤立草稿 |
| 范围与概念协作 | 规则题同步；模型追问异步202；knowledge提供权限过滤候选，models只处理固定输入；用户接受后才形成正式版本 | ScopeQuestionSuggestion与ConceptSuggestion不能直接改ResearchConstraint或ConceptVersion |
| 工作流投影 | Outbox事件更新并在关键命令后立即重算，可从业务事实重建 | 投影延迟不改变审批真值；损坏时重建，不由前端修补状态 |
| 执行与导入 | 一个SearchRun对应一次外部执行，可有多个不可变ImportBatch；完整ResultPopulationVersion才是正式抽样总体 | 重复上传留历史并按固定去重规则合并；部分回传不能声称完整总体 |
| Gold与查准 | Gold正例衡量查全，Gold负例作误检回归；实际结果的全量标注或固定分层随机样本衡量查准 | 废止用Gold正负例直接计算结果查准率；20篇调优反馈默认不作正式查准样本 |
| 抽样治理 | PrecisionSamplingPolicyVersion由数据管理员维护、方法审核者批准，用户选已启用版 | 策略固定置信水平、误差、有限总体修正、分层、最小标注和未判定处理；看结果后不能换版重算 |
| 独立验收 | Gold分区与查准样本组合成EvaluationPackageVersion；任一材料用于调优则整包永久转调优 | 新的正式验收必须使用全新且无暴露的独立包，不能只替换其中一半 |
| 停止、语料与分析 | SearchStopDecision、DatasetSnapshot、AnalysisCapabilityAssessment分离 | validated才显示双85%；停止不自动冻结语料；各模块分别enabled／blocked／exploratory_only |
| 全文许可 | MaterialAccessDeclaration在上传、任务上下文、结果交付三处检查 | 受限材料留待获准处理，不因任务已启动而允许外发或交付派生正文 |
| 演进和验收 | 追加式迁移、兼容读、功能开关；需求→对象→API→状态→测试映射 | 设计、实现、自动测试、真实试点分别记状态；旧状态无依据时必须重核 |

## 3. 核心技术权衡

| 决策与架构编号 | 选择依据 | 放弃或延后的方向／代价 |
|---|---|---|
| Django＋Vue；AD-2、13 | 产品含较多账号、规则目录和审核管理；Django提供内部管理基础，Vue建设研究交互 | FastAPI可满足需求，但须另集成账号和后台；Django不自动实现项目权限或三关审核 |
| 模块化单体；AD-1—3 | 当前规模小，跨对象事务多，共享规则需要统一；独立模块仍可分工开发 | 不先拆微服务；代价是模块边界需CI和代码审查维持，未来拆分要按实测决定 |
| 关系库保存图谱；AD-11、12 | 证据、条件、来源和授权的可追溯性优先；先验证实际查询形态 | 不先建设独立图数据库；大图性能不足时增投影或适配，不把页面图形当理由 |
| PostgreSQL权威任务＋Outbox；AD-6 | 任务受理、状态和事件必须共同提交，队列故障应能恢复 | 增加Outbox、Inbox和租约；事件使用独立stream_seq，完整信封推进游标，仍不能保证供应商只计费一次 |
| 单一模型网关；AD-4、7 | 相同权限、保护集、缓存、预算与成本口径可避免旁路 | 不允许模块直接调用供应商；初期多一层契约，但保留后续替换模型能力 |
| 独立异机关键日记；AD-14、15 | 允许恢复点损失1小时普通数据，同时不能重开已撤内容或盲目重发付费请求 | 增加可重放payload、完成收据和跨存储对账；本地立即拒绝与可靠受理分开，未核清不开放，不假称跨存储原子事务 |
| 内容覆盖显式；AD-5、11、12 | 解析失败、未导出和未知命中不能被当成不存在 | 人工核查仍必要；不通过自动补造结果减少步骤 |
| 单主机＋异机备份；AD-15 | 与已确认试点规模、恢复目标一致，减少部署组件 | 不承诺自动高可用；需要替代主机、密钥和恢复人员才能达到4小时目标 |
| Outbox＋立即重算工作流投影；AD-17 | 事件保证最终一致，命令后重算保证当前页面及时，投影仍可重建 | 增加投影重建与差异监测；不允许把投影当审批或评估真值 |
| projects编排范围、knowledge/models经端口供候选；AD-17 | 正式范围需要单一所有者，同时保留知识和模型专业能力 | 增加候选接受命令；模型不能直接写正式概念或范围 |
| 版本化查准抽样和评估包；AD-5、18 | 查准分母来自实际结果，且调优不能污染独立验收 | 增加抽样治理、标注工作和新包成本；换取可复算、可审计的双85% |
| 停止、语料、分析准入分离；AD-12、18 | 用户可因外部原因停止，语料与各分析能力又有不同条件 | 状态对象增多；避免一个“完成”字段掩盖范围、数据或方法不足 |
| 追加式迁移＋兼容读＋功能开关；AD-15、17、18 | 允许已有试点继续访问，并逐项目验证新流程 | 迁移期间存在历史状态和新状态两种展示，必须明确“待重核” |

## 4. 研发细化与产品决策的区别

UUID、UTC左闭右开区间、Decimal、模块唯一写入、API命令及revision、数据库锁顺序、消息去重、文件指纹和恢复清单是本次研发细化。它们落实已确认目标，没有改变Gold≥50、调优与独立阶段双指标≥85%、候选补查或90天奖励规则。

4 vCPU／16GiB／200GiB、10活动项目测试包、50MiB／300页样例上限、图谱容量包、Worker并发和列表／图视图上限均是初始容量与运行配置，未经实测不能写成保证。超限采取等待、分页、拆分或扩大配置后重测，不据此删除研究材料或降低必要分析覆盖。

科学方法和图谱准入阈值按产品既定机制校准；具体供应商、模型名称、地域、平台格式及授权资产是部署／启用配置。缺少它们不能获得相应正式通过，但不阻止研发实现已确定的状态与接口。

2026-09-10独立复核后补齐：发布事务通过权益模块同步公开命令准备资格；接纳子集变更后贡献者再次确认；预计完整权益区间许可检查；迟到可用性事件回算；个人模板与项目切面独立；模型逐项质量不降低；DRF会话403业务码；30天备份上限内显示实际完整恢复链。均依据既定产品和框架事实整改，没有新增待用户选择的分支。

## 6. 变更规则

AD编号不重用、不因删除而重新排序。改变数据所有者、审批门槛、付费副作用、授权或恢复语义，须补决策事件、修改相关架构规则并更新验收映射。页面布局和实现内部重构不需要重新询问已确认Q1—Q21。若要扩大用户可见能力或改变数据使用边界，才提出新的具体产品决定。
