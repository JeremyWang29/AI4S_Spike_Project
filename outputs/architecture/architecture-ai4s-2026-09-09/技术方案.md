# AI4S 研究决策平台：技术方案总纲

版本：T1.4 模块化整理｜产品基线：V0.14｜更新日期：2026-09-28｜性质：研发契约，非运行验收

采用**模块化单体＋端口／适配器**：Vue 经同域 API 发命令，Django 业务模块拥有数据，Worker 走相同应用服务；PostgreSQL 保存业务事实，RabbitMQ 只通知任务。面向 10 个邀请制账号、3 人同时操作、单项目 2000 条题录与 200 份全文的受控试点。四层产品框架是职责映射，不拆成四套服务。[架构约束](./ARCHITECTURE-SPINE.md)的 AD 编号与规则继续有效。

## 高内聚、低耦合的实现约束

1. **一份业务事实，一个写入者。** 每张业务表由上表的一个模块负责。跨模块只能调用该模块公开的应用命令或只读选择器取得版本化 DTO；不得直接写其他模块的 ORM 表。HTTP、Worker 和 Admin 均走同一服务。
2. **依赖显式化。** 命令携带对象 ID、输入版本／指纹、期望 revision、权限上下文、幂等键及追踪 ID；输出说明结果版本、来源、质量／适用性及恢复动作。异步事件携带因果和版本引用，下游只失效受影响的产物。
3. **不让页面或模型掌握通过权。** 前端只提交用户决定；模型只提交候选。Gold、检索、证据、图谱发布和课题的通过状态由所属模块复核后写入；`WorkflowProjection`只是可重建的读模型。
4. **隔离外部系统。** 平台规则、模型、文件与图谱经端口调用，供应商变化在适配器内处理；任务提交、结果交付和读取时再次校验权限与版本。未配置或失败保留人工路径及明确阻断状态。

## 分模块交付与问题定位

每项任务都按一个纵向切片交付：产品模块规则→技术契约→页面／API→数据迁移→模块测试→跨模块契约测试→验收记录。新模块不能靠复制别人的“已通过”字段完成准入。开发顺序按 M0 入口、M1 检索准备、M2 评估闭环、M3 语料分析、M4 研究决策、M5 图谱共享、M6 质量和试点；可并行的工作也必须先固定交接契约。

故障先按**动作所属模块**定位：登录／越权查 `identity`；建项／范围查 `projects`；检索式或停止查 `retrieval`；导入／PDF查 `materials`；Gold／双85%查 `evaluation`；术语／证据查 `knowledge`；统计查 `analysis`；空白／定题查 `research`；发布／奖励查 `assets` 与 `entitlements`；排队／重试／费用查 `execution` 与 `models`。诊断时按追踪 ID 连接请求、命令、任务、输入版本、事件、投影与审计记录，先检查权限、来源和当前适用性，再检查算法。投影异常从所有者的版本化 DTO 重建，不手工改通过字段。

模块完成检查至少覆盖：唯一所有者、公开契约、异常与恢复、权限与许可、版本和幂等、迁移与回滚、定向测试、跨模块场景、日志／追踪、文档及运行验收证据。具体任务模板、13个代码模块的排障入口及最小诊断字段见[模块开发与故障定位约定](./模块开发与故障定位.md)。设计通过、合成测试通过和真实试点通过应分别标记，不以文档重组宣称功能已交付。
