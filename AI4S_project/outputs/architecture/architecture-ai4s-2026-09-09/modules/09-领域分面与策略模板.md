# T09 立项领域分面与策略模板

<a id="module-entry"></a>

版本：T1.5｜主责：`retrieval` 拥有模板、建议和分面决定；`projects` 拥有项目与正式范围；`knowledge`／`models` 只提供有来源候选｜计划：M1 增量。

对应[产品 P12](../../../research-platform-design-20260907/modules/12-立项领域与一级分面.md)。本模块是**实施契约**，不表示接口或材料／制造模板已经上线。术语 `SearchStrategyFacet` 只指检索策略分面，不复用 `analysis.ResearchFacetTemplate`（研究方向导航切面）的表、状态或通过标识。

## 20. 对象、唯一写入者和状态

| 对象 | 所有者 | 最低字段与约束 |
| --- | --- | --- |
| `SearchStrategyTemplateVersion` | `retrieval` | `domain_code`、版本、适用前提、分面定义、允许的一级关系类型、问题卡、审核人、状态（草稿／待审／已发布／停用）及生效时间；已发布版本不可原地修改 |
| `SearchFacetProposalSet` | `retrieval` | 项目与项目 revision、名称／方向／关键词规范化输入指纹、模板版本集合、授权图谱版本／权限指纹、模型尝试引用、领域候选（最多三项）、候选分面、生成状态和时间 |
| `SearchStrategyFacetProposal` | `retrieval` | 核心对象锚点、分面类型、直接关系类型、候选概念、来源定位、适用边界、理由、歧义、是否需核查及建议用途；模板维度与图谱已证实关系分别标记 |
| `SearchFacetDecisionVersion` | `retrieval` | 所选领域与模板版本、每分面的用途（核心／扩展／筛选参考／暂缓／不纳入）、用户改名／自增内容、决定理由、操作者、期望 revision、确认时间和输入指纹 |
| `ResearchConstraint` | `projects` | 引用已确认的 `SearchFacetDecisionVersion`，独立保存五项字段、用户答案与正式研究边界；不得把提案 ID 当作已确认范围 |

一个提案集可以包含多个领域模板；领域候选不是自动归类结论。手填分面生成用户来源的决策项，不伪造图谱出处。`knowledge` 通过已有最小只读图谱端口返回当前可访问的术语及有类型一跳关系，`models` 返回结构化歧义／补充候选；两者不能写 `SearchFacetDecisionVersion` 或 `ResearchConstraint`。管理员经审核发布模板，不通过更新数据库行暗改已固定的项目版本。

## 20.1 命令与依赖方向

1. `projects` 原子建项成功后发出携带项目 revision 的事件；`retrieval` 只用已保存的项目名称、方向和关键词，按已发布模板与获授权图谱本地生成提案。项目 API 先返回建项成功，不等待模型。无模板或图谱时返回显式降级状态及人工定义入口。
2. 对于跨领域或同名歧义，`retrieval` 最多展示三个候选领域；若需要语义判断且项目外发许可、片段许可和预算满足，则以独立 `facet_disambiguation` 任务请求 `models`。用户主动补充建议可触发相同受控任务。此任务的自动触发只适用于**一级分面建议**；现有“五项字段保存后用户点击生成候选词”的词项网关及输入限制仍照旧。无许可或失败时不得卡死建项。
3. 用户带 `expected_revision`、幂等键和逐项用途确认分面；服务端检查至少一个核心研究对象、模板与项目输入仍适用、关系来源及权限，写不可变决定版本。`retrieval` 公开只读 DTO 给 `projects`；不跨模块写范围表。
4. `projects` 从确认的决定版本生成五项字段参考卡，但不替用户填答案；用户保存并确认 `ResearchConstraint`。`knowledge` 在随后显式请求中依据已回答字段和分面决定细化词项，未回答、探索中和不适用字段不由模型猜满。
5. `retrieval` 创建 `SearchPlan`／`SearchBlock` 时同时引用范围版本、分面决定版本、模板版本与 `ConceptVersion`。分面的“核心”只是任务级必选候选；具体 `required`／`optional` 与任务批次仍由方案追问和用户确认。`not_in_scope` 不转换为查询 `NOT`。

`projects` 的 `WorkflowProjection` 只显示“待确认领域／分面、可填写范围、范围待确认、可生成词项”等导航状态及阻断原因，取值来自各所有者的版本化 DTO；它不能把提案已生成视为用户已决定。旧项目迁移时保留既有范围历史，新门槛只在本增量发布并完成迁移核查后适用。

建议端点语义：`GET /projects/:id/search-facet-proposals/latest` 读取生成／降级状态；`POST /projects/:id/search-facet-proposals` 以幂等键主动重新生成或补充；`POST /projects/:id/search-facet-decisions` 提交逐项用途与用户新增分面；`GET /projects/:id/search-facet-decisions/current` 为范围模块提供版本化 DTO。具体路径在 OpenAPI 实施时固定；所有写命令复核项目成员身份、revision 和输入指纹。模板管理端点仅对受权管理员开放，审核与发布分权并审计。

## 20.2 领域模板和逻辑编译

生命科学模板的建议维度至少覆盖疾病／人群、暴露／干预、机制、结局、癌种／场景及验证方法；材料／制造模板覆盖材料、结构、制备／加工、部件、应用／工况、性能／失效及表征；通用模板覆盖对象、方法／过程、关系、功能／结局、场景和测量。模板中的分面键有稳定 ID，领域标签可变；五项范围字段保留兼容的规范化 schema，并允许材料等领域的显示标签与额外分面引用。新增领域按同一契约添加模板版本，不在代码里追加分散的关键词 `if` 分支。

一跳图谱候选必须有核心对象锚点、类型化边、方向（如适用）、图谱版本和来源定位。模板规则仅建议“应询问哪个维度”，不能冒充某个材料、机制或用途关系的科学事实；模型猜测只进入候选且标明未核查。词项细化仍由 `ConceptVersion` 管理，同一概念内的已接受同义词才是 `OR` 候选；不同分面在 `SearchPlanTask` 中按目的组配。不能把所有 `core` 分面默认全局 `AND`，不能把排除分面默认转成 `NOT`。

## 20.3 版本、任务、测试及分批发布

模板、项目关键词、图谱权限或分面决定变化时，旧提案、决定和引用的范围／方案保留审计历史；通过依赖边将**确实受影响**的下游标为待复核。迟到模型结果先核项目 revision、输入指纹、模板和许可版本；不匹配则保存为过期结果而不覆盖当前候选。缓存键包含租户／项目、规范化输入、模板与图谱版本、权限／许可指纹、模型和提示版本；不同用户或授权域不得共享私有图谱缓存。外部调用失败、未知计费与重试沿用 `models`／`execution` 的受控规则。

验收分层：对象及接口测试覆盖多领域候选、权限、幂等、手填、逐项用途、无模板／无模型降级、迟到结果与依赖失效；每个领域模板至少用两个真实课题由领域专家检查分面适用性、直接关系类型、误扩展和人工可修正性。至少包含“陶瓷切削刀片”“铁死亡—癌症放疗抵抗”，另测跨领域歧义和同一标题不同研究目的。生命科学、材料／制造和通用模板逐个审核发布；未通过的领域只显示人工定义，不宣称智能识别可用。原 M0 建项／范围验收是历史基线，本增量须独立完成真实页面及迁移验收后才能作为新流程门槛启用。
