# 架构覆盖与 rubric walker 审查

日期：2026-09-09。审查范围：产品V0.10、ARCHITECTURE-SPINE.md、技术方案.md、技术决策记录.md、验收与实施映射.md及附带技术资料核查。只进行文档对照，没有执行软件、依赖安装或真实试点。

**判定：有条件通过，完成以下4项明确修订后可交接。** 架构范式、部署规模、数据边界、独立子流程、gold、事件幂等、权限与恢复等主体约束已落实。没有发现需要重新询问Q1—Q10才能解决的架构分叉。以下均可依据已批准产品规则直接补齐，不要求新组件或扩大首版范围。

## 必须修订

### COV-01｜P1｜部分接纳缺少贡献者再次确认的发布守卫

- 产品依据：产品§6.2（第573行）要求管理员改变接纳子集后，回到贡献者预览确认再发布；第571行还规定确认文本、身份、时间、内容指纹。
- 当前位置：技术方案§11第248—252行、§5.2 Publication契约、§12发布命令，架构AD-8。
- 触发情形：用户提交100条关系，管理员剔除20条；审核与许可有效，即按技术方案已有守卫发布80条并发奖。目前没有固定“最后接纳子集已经贡献者确认”的持久事实和原子核验条件。
- 影响：管理员／资产模块与Vue可各自选择是否再次确认，后台合法技术流程可能违反已经确认的用户贡献范围。
- 修订：assets拥有不可变的贡献确认记录，绑定提交版、最后接纳子集及授权说明指纹、贡献者和确认时点。publish要求确认指纹与实际发布包完全一致；范围变化使旧确认不适用并返回待用户确认。补一条部分接纳后未确认、确认后再改子集的拒绝测试。
- 处置：autofix，按产品既定规则补齐。

### COV-02｜P1｜奖励只写当前许可，缺少承诺时段的授权覆盖核验

- 产品依据：产品§6.5第628行明确要求激活及续期前授权能覆盖承诺期限，不足则待领取／待选择；暂停重排也不能把许可失效时段默认为有效。
- 当前位置：技术方案§11第254—258行、§12 activate/transfer接口、架构AD-9。
- 触发情形：资产今天可用但许可证30天后终止，系统仍激活90天；或A尚余60天而B续期90天，许可只能覆盖未来90天却将B排为未来第61—150天。
- 影响：当前时点的权限交集正确仍不足以证明整个承诺期限合法，权益模块可能提前兑换并许诺无法交付的90天。非用户不可用停表不能替代事前已知的期限不合格处理。
- 修订：明确定义计算拟消费区间后，使用当前许可版本检查完整预计区间；激活、续期、转用及队列重排均执行。期限不足保留待领取／待选择或待激活，不增加／消耗额度；暂停导致预计区间延后时重新核验，不能用旧区间审批覆盖新末端。补短期许可与FIFO延期跨越许可终点测试。
- 处置：autofix，按产品既定规则补齐。

### COV-03｜P2｜个人切面模板与项目切面没有明确独立所有权和复制契约

- 产品依据：产品§9.2第820行、§11第930行，要求ResearchFacetTemplate与ProjectFacetVersion独立，首次继承复制，双方后续更新不自动覆盖。
- 当前位置：技术方案§4第82行仅有FacetVersion；§8分析流程、§12接口未定义个人模板及继承／另存命令。
- 触发情形：前端将个人模板版本作为项目当前切面引用；用户改模板后，进行中项目直接受到影响，或者项目修订反写个人模板。
- 影响：泛化版本机制不能代替模板和项目两个可独立修改对象的所有权，分析、项目与前端存在独立实现出不兼容行为的空间。
- 修订：指定唯一负责模块，分别保存个人模板和项目切面版本；项目版本记录来源模板版本但持有独立定义，提供显式继承、升级和另存模板命令。补不自动覆盖、多人项目中个人模板权限不传递、已有报告保持旧版的测试。可沿用同一数据库，无需新服务。
- 处置：autofix。

### COV-04｜P2｜模型质量验收措辞将逐项不降低弱化为“无关键退化”

- 产品依据：产品§12.1逐项标准及用户“在不降低性能的情况下”要求；词表、导航、证据、检索指标、候选及人工工作量均须对同口径基线比较，双85下限不能代替不退化。
- 当前位置：验收与实施映射T12第43行“每项质量及人工工作量无关键退化”；技术方案M4第363行“无关键质量退化”。§10第240行虽列主要检查，仍未消除这两个交接验收口径。
- 触发情形：优化让某非关键词表指标或人工修订时间小幅变差，实施者判为“非关键退化”仍放行；与产品逐项不降低发生分歧。
- 修订：统一成“产品§12.1冻结的各项指标不低于基线、人工工作量不增加，无新增严重科学错误”；如果指标有随机波动，事先冻结重复评测和比较方法，不在看完结果后以不关键为理由放宽。技术总验收直接引用该判定，保留未执行状态。
- 处置：autofix。

## rubric walker 结论

| 检查维度 | 判断 |
|---|---|
| 范式和跨模块分歧点 | 模块化单体、端口适配、唯一写入模块、HTTP/Admin/Worker同命令入口明确；缺口限于上述模板与发布确认契约 |
| AD可执行性 | AD-1—16均包含Binds／Prevents／Rule；版本、租约、指纹、预算、事务和恢复守卫具有可测试输入；AD-8／9按COV-01／02补充 |
| Deferred是否藏阻断 | 供应商、精确补丁、科学阈值、授权资产均给出启用前核验和未配置行为，未要求研发自行虚构科学规则；不构成新增未决产品问题 |
| 用户Q1—Q10 | 研发实施、多人工具、受控服务器、10账号／3并发／每项目2000题录200全文、许可交集、选择性迁移、Vue/Django、文字PDF及人工、恢复与保留均有对应设计 |

| 部署与运行 | 环境隔离、单主机限制、Worker并发、共同恢复点、异机日记、备份水位、恢复人员及目标验收覆盖；没有用同机备份冒充灾备 |
| 原文与授权 | 来源、定位、提取覆盖、人工核查、派生内容继承、各取用点许可、删除恢复和外部副本边界明确 |
| 技术来源 | 附带官方资料核查与支持期，精确锁文件在M0验证；本审查未重复网络核查或将文档兼容性认定为实测 |
| 验收真实性 | S01—S16与T01—T12均标为测试规格，真实选题、容量、费用和恢复目标待测；不伪造已通过 |

没有要求新增微服务、图数据库、向量服务、OCR或GPU；这些不构成当前10账号试点的必然前置条件。本报告提出的是已有产品约束落到共同契约的缺口，不代表软件实现存在已证实缺陷。
